# 顔検出の比較を再開する手順（#79 / #406）

## 今の到達点と次の一区切り

- 評価専用の ML Kit FAST / ACCURATE、YuNet があり、製品の依存と画面には未接続。
- 合成黒画像で各11回の接続状態の smoke が成功済み。これは初期化と顔なし入力の疎通であり、
  顔の精度、初回オフライン、Pixel の性能を合格としたものではない。
- 次の区切りは「同じ画像の3方式の結果と、人の正解ラベルによる比較を非公開で確認できること」。
  ML Kit を第一候補とするが、YuNet との一致率だけで採用を決めない。
- private RGBA入力runnerとmanifest検査を追加した。実写や顔入り入力の実走は未実施。
  詳細は [入力手順](PRIVATE_INPUT.md)。下記は未実施部分も含む作業順序。

## dot で先に行う作業

1. 集計の比較予定リストを固定し、方式全体・条件全体の未実行を明示する。
   `evaluate.py --detector` を各方式に指定する。存在しない方式を成績の良い「顔なし」にしない。
2. 独立評価projectだけに、ローカル素材 manifest の検査と入力runnerを追加する。
   ファイルhash・寸法・向き・画素形式・前処理revisionを一致検査し、差があれば実行しない。
   入力は本人が承認した素材だけ。ネットワーク取得機能・画像送信機能・製品依存は加えない。
   SAF等の経路を新設する場合も評価アプリ内に限定し、製品UIに接続しない。
3. 個人写真を使う前に、非個人の許諾済み顔入り素材または合成素材で入力・出力・再実行の
   手順を試す。合成の顔での成績を実写精度へ読み替えない。黒画像は負例の疎通として残す。
4. 本人へ素材の選び方・ローカルの保存先・操作・所要時間を提示してから、実写／Pixelへ進む。
   写真、切抜き、顔枠、画像別値、個人用パスはGitHubへ載せない。

PR-D・初回表示の実装とは独立worktree。ホスト集計はAVD不要。Android試験では最新の
`docs/MANAGED_DEVICES.md` と AVD 運用手順を使用し、専用ポート・ANDROID_SERIALを固定する。
速度比較は1台だけで行い、画面の試験やGPU試験と重ねない。Pixel操作は毎回本人の承認後。

## 評価条件（採用前に固定）

| 軸 | 分けて確認する条件 |
|---|---|
| 顔の向き・大きさ | 正面／斜め／横顔、小さい顔／大きい顔、単独／複数 |
| ステージ環境 | 明るい照明、逆光、色の付いた照明、暗部、照明の縁 |
| 隠れ・誤検出 | 髪・手・マイクによる部分遮蔽、顔なし、衣装や背景の顔らしい模様 |
| 用途 | 撮影補助と外部DNG現像を分離。Camera2の情報は外部DNG比較の候補にしない |

最初の実写確認は本人が選ぶ少数の代表写真で誤検出・見逃しの傾向を見る。
その枚数で採用の統計的な優位性を断言しない。正解ラベルを検出結果から自動生成しない。
完全遮蔽・判別不能・極小顔の対象／除外基準と、IoU照合閾値は結果を見る前に固定する。
既存設定（ML Kit minFaceSize 0.1、YuNetの回転探索と閾値）は同じ意味の閾値ではない。
まず固定設定の挙動を比較し、調整するなら tuning と held-out を分け、held-outで閾値を選ばない。

## 何を比べ、何は未決定に残すか

- 精度：人ラベルに対する TP / FN / FP、条件ごとの見逃しと誤検出。顔枠の位置・被覆も
  本人が確認する。全体平均だけで暗いステージや小顔の欠点を隠さない。
- 時間：初期化、first-call、warmのSDK時間／変換込み／bitmap複製込みを分離。
  同一画素・同一端末・同一設定で直列測定。各方式の測定順を入れ替え、熱と待機条件を記録。
  AVDは手順確認と同一AVD内の参考。Pixelの実測の代わりにはしない。
- 容量：同じABI・縮小・署名条件の完成APKとbaselineとの差。既存debugの2ABIの値を
  製品arm64の配布差として使わない。採用候補が決まれば同条件の配布向け構成で再測定。
- ライセンス：固定SDK／OpenCV runtime／YuNetモデルと推移依存を別々に棚卸しする。
  既存inventoryとnotice収載は出発点。配布前に不足noticeを確認し、収載件数だけで完了しない。
- オフライン：bundled ML Kitの初回起動、再起動、warmを分ける。通信が完全にないことを
  要求しない。SDK診断ログの許容と、写真／顔結果を送信しない境界を維持する。
  ネットワークや端末のセキュリティ設定を独断で変更しない。

顔測光・白飛びガード・肌マスクへの接続、撮影時のCamera2併用、製品依存、採用閾値は別の判断。
比較結果を示して本人が方式を選んでから、小さな製品接続案にする。今回の評価整備では実装しない。
