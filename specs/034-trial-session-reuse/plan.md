# 設計

PrivateTrialReuseRegistryは単一active sessionを保持する。sessionは一つのkey/entryとrequest binding revision、epochを持ち、leaseは小さなmetadataだけを持つ。Sessionからregistryを呼ばずlock順を固定する。closeは画素参照を落として旧leaseを失効させ、in-flight kernelの実停止/closeは既存coordinatorに任せる。

AndroidAutoDevelopQueue.preparePrivateTrialの既存IO allocator内でopt-in sessionをbindする。adapterはattempt作成時、BackendはprivatePreview開始時にleaseを一つ固定する。旧job/backendへ画素を置かない。legacy prepareはbindingを外し、明示再bindのための同一entryは保持する。

JpegGenerationAttemptは原本確認後にbaseを取得する。hitでは同じ空ROI/顔NOT_RUN/診断EVの一時controlsを作り検証し、Lookから実行する。missでは従来通りdecode/inputs/R7を実行する。成功JPEG・原本post hash・stream close確認後にだけbase候補を登録し、adapterの追加close失敗でも無効化する。単なる取消は以前の正常entryを残すが、候補を完成と扱わない。

比較はpost原本hashと全FD/stream close後にfresh IntArrayを登録する。hitでも既存JPEGと原本のfresh確認を行い、cloneした画素から新Bitmapを作る。allocation失敗等は既存decodeへfallbackし、内容変更・中断・close未確認の扱いを緩めない。

PhotoRollRendererへoptional discardTransientInputsを追加し、選び直し・一覧/終了・pause/disposeへ接続する。Activityのlow/trim通知、DevelopExecutionの撮影予約・blocked条件はsessionを閉じる。通常の強度更新は同sessionを再bindし、既存のUI取消/世代/ticket判定は維持する。
選択写真の検査失敗は、Main上のselection/strength両ticketが現在と一致する場合にScreenが破棄する。checkOriginalはstatelessを維持し、古い検査のlate errorから現在sessionを閉じない。通常の取消/検査停止はこの実エラー破棄から除外する。

既存のmax1024/quality95/Stage Clear演算・snapshot・公開gateは変更しない。土台再利用だけでLookの時間はなくならないため、Look段階計測と512等の縮小比較は別のローカル診断で行う。軽量previewの品質/解像度、原寸ROI/GPU、全体統計/blur fieldの共有方式は採用しない。
