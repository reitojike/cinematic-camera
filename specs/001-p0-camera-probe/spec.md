# Feature Specification: P0 RAW・マニュアル露出の成立性検証

**Created**: 2026-11-01

**Status**: 合意済みP0仕様（共有保存要件を含む）

この文書は確定した振る舞いと受入条件を定義する。最終検証結果と採否根拠は
[P0_REPORT.md](../../docs/P0_REPORT.md)、AC対応の完了状態は[tasks.md](tasks.md)を参照する。
日々の進捗・確認のやり取りはIssue等で管理し、検証の進捗に合わせて仕様本文を変更しない。

**Input**: 2026-11-01に合意したCinematic Camera P0ブリーフ。既存の技術検証アプリを
作り直さず、合意した振る舞いと受け入れ条件を記録する。

## User Scenarios & Testing

各storyのPriorityは本P0内の優先度であり、将来の開発フェーズP1〜P4とは異なる。

### User Story 1 - 撮影を開始し、カメラの能力を把握する (Priority: P1)

検証者はPixel 9aで権限を許可してプレビューを開始し、停止・再開・背景復帰を試す。
各カメラの能力と、撮影基盤が実際に提供する出力形式を区別して確認する。

**Why this priority**: 撮影や露出検証の前提であり、非対応を誤って対応扱いにしないため。

**Independent Test**: 写真を撮らずに許可、開始・停止・復帰、能力表示とログを確認できる。

**Acceptance Scenarios**:

1. **Given** 初回起動で未許可、**When** 許可する、**Then** プレビューが始まり状態が表示される。
2. **Given** プレビュー中、**When** 停止→開始、または背景→復帰する、**Then** 再び撮影可能になる。
3. **Given** カメラ一覧を取得可能、**When** 能力を表示する、**Then** ID・レンズ識別・ハードウェア
   レベル・RAW/手動対応・ISO/時間範囲・最小フォーカス距離・F値・RAWサイズ・出力形式が記録される。
4. **Given** 非対応・取得失敗、**When** 選択または操作する、**Then** 前カメラの能力を流用せず理由が表示される。

### User Story 2 - RAW素材を保存し、有効性を確認する (Priority: P1)

検証者は対応カメラでDNGを保存し、PCのRAW viewerで開けるかを調べる。
対応する場合だけRAW+JPEG同時保存も別に試す。

**Why this priority**: 後続のRAW現像へ進める素材が得られるかを判断するため。

**Independent Test**: AUTOのまま、対応カメラで保存とPC読み込みを検証できる。

**Acceptance Scenarios**:

1. **Given** RAW出力対応が確認できる、**When** 各保存完了を待って5回以上撮る、**Then** 別々のDNGが
   共有の`Pictures/Cinematic Camera/`に保存され、ファイル名・URI・byte数が確認できる。
2. **Given** 保存した5件以上のDNG、**When** PCのRAW viewerで各ファイルを開く、**Then** 成否・viewer名・
   サイズ・内容確認を記録する。非ゼロbyteだけでは有効と判断しない。
3. **Given** RAW+JPEG対応、**When** 同時保存を選ぶ、**Then** 同じ撮影に対する両方の保存結果を確認できる。
4. **Given** RAW非対応または保存失敗、**When** 撮影を試す、**Then** 理由を確認でき、成功回数に含めない。

### User Story 3 - 指定した露出が実測に反映されるか確認する (Priority: P1)

検証者はAUTOからMANUALへ切り替え、ISOと露光時間を変更し、指定値と実測値を比較する。
AUTOへ戻したときに手動設定が残らないことも確かめる。

**Why this priority**: 設定の受付だけで成立と判断せず、センサーの結果で後続の採否を決めるため。

**Independent Test**: 画像の見た目に頼らず、範囲内の設定と実測ログで比較できる。

**Acceptance Scenarios**:

1. **Given** 手動対応と有効範囲を確認済み、**When** ISOを2値以上、時間を2値以上切り替える、**Then**
   指定・受付・実測を区別して比較し、誤差・フレーム周期などの制約を記録できる。
2. **Given** MANUAL中、**When** AUTOへ戻す、**Then** 手動上書きが解除され、プレビューが止まらない。
3. **Given** MANUAL中、**When** カメラ/出力を変更、またはStop→Startする、**Then** AUTOへの解除受付を
   待ってから撮影できる。過去のcallbackが新しい操作状態を書き換えない。
4. **Given** 範囲外入力・非対応・設定失敗、**When** 適用する、**Then** クラッシュせず理由と回復手段を確認できる。

### User Story 4 - 新撮影を標準ギャラリーから見つける (Priority: P1)

検証者は撮影したJPEG/DNGを共有画像フォルダー`Pictures/Cinematic Camera/`で見つける。
新しいギャラリーUIは作らず、Googleフォト等の既存アプリから確認する。

**Why this priority**: 内部保存でファイルを見つけられないというユーザーの追加要件を解消するため。
**Independent Test**: 新しいJPEGを撮り、保存URI/byte数と標準ギャラリーの表示を確認する。

**Acceptance Scenarios**:

1. **Given** 撮影可能、**When** JPEGを保存する、**Then** 指定の共有フォルダーに画像が登録される。
2. **Given** RAWまたはRAW+JPEG対応、**When** 保存する、**Then** DNGとJPEGを再エンコードせず保存し、
   各URI/byte数を記録する。DNGが閲覧アプリで開けるかはJPEGと別に確認する。
3. **Given** 書込みや公開に失敗、**When** エラーを処理する、**Then** 今回作った未完了画像を片付け、
   完了扱いにしない。旧内部ファイルは不要に削除しない。
4. **Given** 旧版の内部写真、**When** 新版を使う、**Then** 一回限りの移行機能は追加しない。
   今回の既存テスト写真の消失許可を、将来の一般的なデータ消失許可に広げない。


### Edge Cases

- 許可の拒否・恒久拒否、端末背景化、Activity再生成、他アプリによるカメラ占有。
- カメラ自体のRAW能力と撮影基盤の出力対応が異なる、出力組合せで開始できない。
- RAW+JPEGの片方だけが保存される、保存先の作成・書込みが失敗する。
- ISO/時間範囲や結果が取得できない、受付成功後の実測が指定と異なる、長時間露光で低fpsになる。
- 停止・切断後の遅れた結果、AUTO解除失敗、過去IDの能力が画面へ残ること。
- 共有画像の行作成・ストリーム書込み・公開の失敗、RAW+JPEGの片方の失敗、閲覧アプリのDNG非対応。

## Requirements

### Functional Requirements

- **FR-001**: 権限、プレビュー、lifecycle、明示的な開始/停止を検証できなければならない。
- **FR-002**: 各カメラIDの能力と撮影基盤の出力形式を別々に画面とログへ記録しなければならない。
- **FR-003**: 対応を確認した形式だけ選べ、新しいDNGと任意の同時JPEGを共有画像フォルダーへ保存しなければならない。
- **FR-004**: AUTOと、範囲内のISO/露光時間を指定するMANUALを切り替えられなければならない。
- **FR-005**: 指定値・受付結果・実測値を混同せず記録し、AUTO復帰時の上書きを解除しなければならない。
- **FR-006**: 状態・エラー・非対応理由・保存先・能力を最小UIで確認でき、失敗を成功扱いにしてはならない。
- **FR-007**: 固定絞りは表示のみとし、操作UIを作ってはならない。実機非対応時に独自回避を増やしてはならない。
- **FR-008**: 端末、Androidビルド、アプリ版、カメラID、能力、撮影/露出結果、DNG読み込み、失敗条件、
  制約、次フェーズの採否判断をレポートへ残さなければならない。
- **FR-009**: 撮影物と完全な実機ログは公開履歴へ入れず、位置情報・画像本体をログへ含めてはならない。
- **FR-010**: 新撮影を`Pictures/Cinematic Camera/`へ登録し、保存完了のURI/byte数を記録する。
  広範囲のストレージ権限、独自ギャラリー、SNS機能、既存写真の移行/一括削除は追加しない。
- **FR-011**: 書込み中は未完了として扱い、全出力成功後に公開する。失敗時は今回作った画像行を片付ける。

### Key Entities

- **カメラ能力記録**: ID、レンズ、ハードウェアレベル、RAW/手動対応、範囲、固定F値、RAWサイズ、出力形式。
- **露出観測**: 希望ISO/時間、受付状態、requestとresultのAE/ISO/時間、frame番号、時刻、frame duration。
- **撮影結果**: 撮影token、形式、ファイル名、保存先、byte数、保存結果と別のviewer確認状態。
- **P0判定**: ACごとの証拠・未確認・BLOCKED理由と、GO / GO_WITH_LIMITATIONS / NO_GO / 未判定。

## Success Criteria

### Measurable Outcomes

| ID | 合格条件 | 対応要件 |
|---|---|---|
| AC1 / SC-001 | Pixel 9aで許可・preview開始/停止/復帰を確認する | FR-001 |
| AC2 / SC-002 | 実機の能力一覧を画面/ログに記録する | FR-002 |
| AC3 / SC-003 | 対応カメラでDNGを5回以上保存し、PC viewerで全件の有効性を確認する | FR-003 |
| AC4 / SC-004 | ISOと露光時間をそれぞれ2値以上変更し、実測への反映・誤差・制約を記録する | FR-004, FR-005 |
| AC5 / SC-005 | AUTO→MANUAL→AUTOでプレビュー停止やクラッシュがない | FR-004, FR-005 |
| AC6 / SC-006 | 非対応・APIエラーをクラッシュさせず画面とログへ記録する | FR-006, FR-007 |
| AC7 / SC-007 | ビルド・実機証拠・制約・次フェーズ判断を`docs/P0_REPORT.md`へ残す | FR-008, FR-009 |
| AC8 / SC-008 | 新JPEGを共有フォルダー/標準ギャラリーで確認し、DNGの登録と閲覧対応は別に記録する | FR-003, FR-010, FR-011 |

AC3/4が実機仕様で不成立なら、根拠付きの`BLOCKED / 実機非対応`として調査成果に残す。
SDKや端末が使えないことを実機非対応・合格の証拠にしない。現状の証拠と合否は
[P0_REPORT.md](../../docs/P0_REPORT.md)を参照し、ここでは実機合格を宣言しない。

## Assumptions

- 最初の対象はGoogle Pixel 9a。端末間互換性、画質・性能の定量最適化はP0対象外。
- P0は完成版の撮影体験ではなく、後続の技術選択を判断するための最小アプリ。
- 映画的な色、Teal & Orange、21:9、RAW現像、写真/動画のルック再利用、JPEG/MP4、SNS共有は将来の方向性。
  P0では現像、NDK、フィルター、GPU/LUT、動画/HDR、21:9保存、ギャラリー、SNS、クラウドを実装しない。
- ユーザーが指定した技術制約と正確な採用版は[plan.md](plan.md)で追跡する。
- 未解決の要件上の曖昧さはない。成立性は実機計測で判断するため、未測定値を推測で埋めない。
