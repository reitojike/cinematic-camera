# 編集復帰と原寸書き出しのライフサイクル（#81 / #89 / #143）

## 目的・範囲

同じ写真・同じ編集設定へ復帰した際の不要な再現像を省き、原寸書き出しの中断・再試行・重複防止の
所有権を明確にする。画素処理、GPU、撮影、既存配布APK、原本、実写の品質判断は変更しない。
縮小表示と原寸保存は別の仕事であり、表示のキャッシュhitを保存成功や再公開の許可に使わない。

## 振る舞い

- 最後に処理へ提出した強度/WB/EVをアプリ切替で維持する。指を離す前の未提出値は破棄する。
  明示的な「取消」は編集開始値へ戻る既存操作のまま。停止前の指や結果を再開後に採用しない。
- ViewModelに保持するのは、ソフトウェアsRGBの長辺1024以下のBefore/After一組だけ。
  キャッシュは合計8MiB上限で、原寸画素・RAW配列・FD・Activity・公開receiptを保持しない。
- 復帰時も原本の読取権限・fingerprintを既存経路で再確認する。同じURIだけではhitとしない。
- URI/原本hash/サイズ/grant、強度、WB、EV、look版、表示サイズ、modeが違えば再利用しない。
- 低メモリ・明示再試行・終了で破棄する。UI_HIDDENだけでは表示キャッシュを破棄しない。
- process deathで画素は復元しない。既存rememberSaveableの選択と小さい編集値から権限・原本を
  再検証して再現像する。BitmapをBundleやSavedStateHandleへ格納しない。

## 原寸書き出しの現在の境界

現行保存は明示操作・前景条件・単一IO/資源ownerが必要で、今回それを黙って緩めない。
アプリ切替による実行中書き出しの取消は残る。中断後に「成功」「新規生成可能」と推測しない。
公開journalに証拠がある場合だけ同じ保存を照合し、公開成否不明や生成開始intentだけの場合は
自動再生成しない。OS schedulerのretryを既存保存ownerへ直接接続しない。

## 受入条件

- 同じ検証済み入力/全設定でhitし、変更・低メモリ後の遅延書込み・別ownerのticketは拒否。
- 保存handleを現行世代から再取得し、UI用Bitmapはキャッシュとは独立所有とする。
- 合成状態試験で取消前/提出後/保存途中/公開後/再起動を区別し、重複生成・公開を防ぐ。
- 背景保存のAPI比較・owner境界・安全にretryできない箇所を記録する。
- 実機速度・process death・低メモリ通知のAndroid実動作と24MPの成否は未確認として残す。
