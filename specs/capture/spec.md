# 撮影と制御の現行仕様

メッセージの枠・優先順位・トーン・文言・アクセシビリティは [共通メッセージ仕様](../ui-messages/spec.md) を参照する。
共通部品の追加だけで既存画面を切り替えず、画面適用は別PRで行う。

## 現在の契約

- STILL / CINE と、ISO・SHUTTER・EV・FOCUS・WB・LOOK の6キーを等幅の横一列に配置する。撮影用 LOOK の入口があることを、撮影映像へのルック適用済みとみなさない。
- 縦のレイアウトを基準に保ち、向きの扱いは自動回転設定に従う。設定・診断の本文を端末の向きに合わせて新たに回転しない。静止画の向きは撮影時、動画は録画開始時に確定する。
- 設定シートを開いても撮影プレビューの寸法・画角・セッションを変えない。背後へのタップ貫通を防ぐ。
- ISO/SHUTTER は撮影対象値を即時選択する。EV/WB/MF は処理中にも最新の有効な意図を保持し、遅れて届いた応答で巻き戻さない。送信済み意図を目盛りの外側タップで取り消さない。
- 要求・API受付・実測は別の情報として表示する。AUTO の実測表示は表示専用で、撮影設定へ書き戻さない。未取得・古い接続・期限切れの値を実測として補完しない。
- 露出だけ AUTO に戻す操作と、撮影制御の全リセットを分ける。全リセットには確認を設ける。
- 状態バー・通知・診断の役割を分け、録画開始要求と実際の録画、停止と保存完了を区別する。録画赤は実録画に使う。無効理由を色だけで伝えない。
- 目盛りは中央選択・左右の操作・標準の触覚フィードバックを持ち、端点や同値で余分な送信や触覚を起こさない。OS の触覚設定を尊重する。
- 手動シャッターの暫定上限は1秒。これは長秒露光の根因が解決したことを意味しない。異常時の再接続は撮影・保存の所有状態を確認し、安全でない間は拒否する。
- Camera2 が端末から取得する能力と CameraX が選択可能と報告する撮影形式は区別する。CameraX で対応を確認できない形式への切り替えやバインドは行わない。固定絞りは診断で表示するだけで操作対象にしない。

## 撮影画角と AUTO 実測の補足

- CINE の Recorder は 16:9 に設定する。Preview と VideoCapture は、縦固定の画面座標で 9:16 の共通領域（`ROTATION_0`、`FILL_CENTER`）を使う。FPS 範囲は組合せごとに選び、対応判定に通った同じ `SessionConfig` を実際のバインドにも使う。静止画にこの設定を適用しない。CameraX の受付は、プレビューの表示・録画ファイルの縦横や実画角の一致を保証しない。
- ISO・SS の AUTO 主値では、表示更新時に、現接続のプレビューまたは録画の有効な取得結果のうち、受信時刻から2秒以内の値だけを採用し、標準候補へ近似表示する。表示を再利用して期限を延長せず、期限切れ・別接続・未取得の値は実測として表示しない。丸めた表示値は撮影設定へ書き戻さない。

## 通常 STILL MANUAL の露出プレビューと撮影

- 撮影に使う ISO・シャッター速度と、表示用のプレビュー設定を分ける。プレビューは同じ絞り・共通ゲインでの ISO×露光時間を近似する。追加ゲインの指定は対応端末に限る。端末の露光範囲・フレーム周期と ISO の補償余地が許せば短い露光を使い、足りなければ有効範囲内で露光を長くする。撮影設定の暫定1秒上限はこの切替閾値ではない。
- 能力値が不明・不正、または条件を満たす組合せがないときは、値を作って送信しない。プレビュー設定の受付やセンサー結果だけで、撮影との画質・明るさの一致や描画fpsを保証しない。
- シャッターを押した時点の撮影設定を固定し、プレビューの補償値ではなく、その撮影設定の新しい受付後に単発撮影する。JPEG と RAW の両方を要求した場合、一方だけの完了で所有を解放しない。全出力の結果、または確定した撮影失敗を処理した後、最新のプレビュー設定に戻し、新しい受付と現接続のプレビューフレームを確認してから撮影可能に戻る。
- 単発撮影をまだ開始していない準備失敗は復帰できる。開始後、結果がないまま期限を超えた場合は結果不明として撮影設定と所有を保持し、成功・取消・保存失敗とみなさない。結果が確定するか、明示的な停止・背景化などで接続世代が無効になるまで、競合するプレビュー設定で上書きしない。旧接続・旧要求の受付や撮影用の観測値を、現在のプレビューの証拠にしない。

## プレビューの測光と録画の継続条件

- 測光できるとき、プレビューのアクセシビリティ操作は画面中央、物理タップはその位置で1回だけ、利用可能なAE／AFを要求する。タップに伴うクリック通知で中央へ重ねて要求しない。
- 設定・診断パネルの操作や閉じる操作を、背後の測光として扱わない。Backは表示中のパネルを閉じる操作として扱い、撮影・録画中の既存ガードを維持する。目盛り表示中のプレビュータップは、目盛りを閉じるだけで測光しない。 診断表示中は背後の撮影バー（撮影・録画、モード切替、写真一覧）を、キーボードや読み上げからの操作も含めて無効にする。録画が開始準備以降の状態になった場合は診断を閉じ、停止操作を覆わない。
- 録画の出力方向はUIの自動回転設定と独立し、開始時から終了処理まで固定する。設定の開閉や端末の向きの変化では録画を止めず、録画停止の操作を維持する。アプリを離れると録画を停止する。

## ISO・シャッター速度の即時選択と応答期限

- ISO・シャッター速度は端末の能力とフレーム周期、該当する撮影モードの制約に収まる標準段階から選ぶ。AUTO から初めて片方を選ぶときは、同じ接続の有効な ISO・露光時間の元実測を使い、合法な候補の組に合わせて選択した側を置き換える。表示の丸め値を使わず、どちらかの元実測が欠ける、期限を過ぎる、または合法な組がない場合は値を作って送らない。すでに MANUAL の場合は最新の論理上の撮影設定を基にする。
- 制御の送信は同時に1件、次に送る候補は最新1件に限る。要求の接続世代と操作トークンを照合し、期限切れや古い応答を現在の受付に使わない。設定がいつ反映されたか不明な状態では最新の意図を保持するが、同値の選択を自動再試行の起点にしない。安全条件を満たす明示的な AUTO または再接続で復旧する。
- 制御の応答期限には要求露光時間・同じカメラについて保持している過去の要求露光時間・実測フレーム周期を使う。より長い露光時間を要求したときは受付前でも保持値を長い側へ更新し、応答が不明でも同じカメラの再接続後の期限見積もりに使う。保持値を短くする、または消去するのは、新しい露出または露出指定の解除が受け付けられてからに限る。この保持値を実測や受付済み撮影値、永続化する設定として扱わない。

## 通常MANUAL撮影targetの暫定1秒上限

- 通常MANUALの新しい撮影targetは1秒以下に限定し、1秒超の直接入力は黙って短縮せず拒否する。これはアプリの暫定policyであり、端末の露光能力の報告値を書き換えない。
- SS候補は端末の露光範囲・最大frame周期・暫定1秒上限の交差から選ぶ。CINEでは要求fpsのframe周期とも交差させる。最短側の標準SS、ISO系列、要求fpsはこの上限のために変更しない。
- STILLの起動・再bind・背景復帰で旧1秒超のMANUAL保存値/復帰targetを受け取った場合だけ、ISOを保持して現在の交差内の最長標準SSへ明示移行する。初期preview seedとruntime復元で同じpolicyを使う。旧露光が現在の端末上限より長くても、構文・正の時間・現ISO範囲を先に検証し、移行後targetを現在の露光範囲へ照合する。
- 1秒以下の旧targetをこの移行で再量子化しない。保存pair欠落、不正値、ISO範囲外、移行に必要な標準ISO/SS候補なしでは架空のpairを送らず停止する。候補がない場合はAUTOまたは接続停止による復旧を案内する。
- 旧値から新targetへの移行要求を共通noticeと診断へ示す。runtimeの新API受付前や失敗時には移行先を受付済み保存値にしない。受付後だけ移行したpairを保存し、再bindで同じ値を維持する。preview API受付、シャッター時の撮影API受付、センサー実測は別の証拠である。
- AUTOは手動露出override解除であり、独立した制御を保つ操作と全リセットを区別する。保持中の旧MANUAL復帰要求を残さず、既存の所有権・queue・世代境界を維持する。AUTOのAE実測露光が1秒以下になる保証はしない。
- 暫定上限は長秒capture freezeの根因解消ではなく、既にセンサーへ送った長秒処理の即時終了も保証しない。実機の移行notice・actual・撮影/復帰時間・RAW回帰は、別途の対象版/条件の確認がない限り未確認として扱う。

## 検証の境界

要件・純粋状態テスト・実描画・実機受入は別々に扱う。端末が受付したことだけでセンサー反映、合焦、画質、保存物の妥当性を証明しない。
P0の成立性調査と現在の製品機能を混同しない。古いP0の対象外一覧は、後続でマージしたRAW現像などを禁止する現在の一覧ではない。

## 撮影メッセージの熱拒否表示

録画開始の既存熱判定が拒否したときだけ、表示専用の連番を更新し、画面はその新規イベントから4秒間 FAILURE を表示する。録画受付条件は変えず、通常の高温状態は WARNING、過去の拒否を画面再作成時に再通知しない。
通知の NORMAL / ACCEPTED は発生元が型付きで渡し、文言の一致で色を決めない。初回カメラ権限は FAILURE の共通 PROBLEM（見出し「カメラを使えません」、本文「カメラの許可が必要です。」）から既存の［カメラを許可］へ接続する。
上部チップは固定の設定ボタン領域を除いた幅で行を折り返し、MIC や熱のチップを途中で隠さない。プレビュー上端と縦画面バナーは実測したヘッダー高さに追従する。熱拒否 FAILURE の線は Failed、通常 WARNING は Amber を使う。

熱チップは OS 深刻度 1〜6 を WARNING/Amber に統一し、SEVERE・CRITICAL 等の文字と読み上げ説明を維持する。0・不明は NORMAL。開始拒否や停止の制御条件（3以上）は変更せず、操作の失敗は既存の赤いバナーで伝える。
