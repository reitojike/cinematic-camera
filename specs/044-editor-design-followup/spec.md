# Feature Specification: 現像デザインの差分修正

**Feature Branch**: `fix/editor-design-followup`
**Created**: 2026-11-07
**Status**: Draft

## User Scenarios & Testing
### User Story 1 - 調整対象を識別する (P1)
編集中の対象と未反映状態を一目で区別できる。
1. 編集開始・対象切替で、対象キーだけ選択背景と上辺3dp線を表示し、選択状態を読み上げる。
2. 編集を閉じる・取り消すと選択表示がなくなる。
3. 画像→目盛り→キー→保存列の順に表示する。
### User Story 2 - 原本情報へ到達する (P1)
長いファイル名でも戻る・原本情報を横スクロールなしで操作できる。中央の状態だけ横スクロールする。
### Edge Cases
狭幅、大文字、横向き、未対応キー、背景移行、未反映、保存確認中、比較画像なしでも既存操作制約を維持する。

## Requirements
- FR-001: 選択表示は編集中の対象キーだけ。色だけでなく線と読み上げで識別する。
- FR-002: 目盛りをキーの上へ置き、未反映の指標はアンバー、無効は指定の灰色とする。
- FR-003: 戻ると原本情報は状態帯両端に固定し、中央の内容はスクロール可能とする。
- FR-004: 撮影と現像のキー、目盛り見出し、表示切替の視覚表現を共有する。入力方式は変更しない。
- FR-006: モードチップと顔保護注意は上記のモード別表示を使い、注意とモードを混同しない。
- FR-005: 連続相対ドラッグ、離して確定、1段タップ、RESET、取消、セッション境界、キーボード、支援技術、保存制約を維持する。比較キーと下段切替、長押しも残す。

## Success Criteria
- SC-001: 編集対象の変更と終了で選択状態が一致し、表示順が全例で一致する。
- SC-002: 長い名前でも原本情報を横スクロール0回で開ける。
- SC-003: 既存入力・保存の回帰試験が成功する。

## Assumptions
spec042の見た目だけ変更する採用判断を維持。全範囲5ラベルを維持し、近傍候補への変更は別途判断。モード色は縮小試験「試験 1024px」だけアンバー、他は白枠。「顔保護なし」はStage Clearのみ非表示とし、手動・縮小試験と既存legacy trialの注意を維持。
RAW、24MP、保存owner・foreground save、lifecycle・Bitmap、PhotoRollScreen callbackは対象外。依存追加なし。
