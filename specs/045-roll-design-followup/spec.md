# Feature Specification: カメラロールの権限案内と空状態の補正

Branch: `fix/roll-design-followup` / Status: 実装・合成検証済み、実機未確認 / Issue作成許可待ち。
既存041・Issue #174の追加修正。2026-11-06 design-handoff のINSTRUCTIONS.mdを文言と数値の正とする。

## User Scenarios & Testing

### US1 閲覧可能な範囲を正しく理解する (P1)
写真・動画を全面許可済みなら、不要な許可案内に一覧の領域を使わない。一部だけ許可した場合は、残りを許可済みと誤認しない。
受入: 全面許可では許可帯を出さない。部分アクセスは破線アンバーの枠・文字と「選び直す」「設定」を表示する。写真だけ全面許可など混合状態は既存の正確な説明を保持する。未許可と非対応も事実どおり案内する。

### US2 一覧が空でも次の操作を選べる (P1)
受入: 読込中でなく一覧が空なら、中央に説明と「アクセスを許可」「Filesから選ぶ」がある。各操作の有効条件は既存のまま。読込中は空状態を確定表示せず、既存タイルを消さない。

### US3 一覧を統一した色で読む (P2)
受入: サムネイル待ち・代替表示は画面共通のパネル色・文字色・書体を使い、テーマ既定の紫がかった色を残さない。3列・間隔2dp、日付・種類タグ・直近の緑枠は維持する。

## Functional Requirements
- FR-001: 許可帯は全面許可では省略し、それ以外は既存アクセス状態を正しく伝える。部分許可の注意は文字と破線で識別できる。
- FR-002: 空状態には中央の案内と2操作を用意する。操作は既存の権限要求とFiles選択へ委譲する。
- FR-003: フィルタ後の空一覧と権限なしを断定せず、どちらも確認できる説明にする。読込中・既存タイル・追加読込の意味を変えない。
- FR-004: サムネイル待ち・代替表示の色と書体を既存の共通トークンに合わせる。outlineや他画面の再構成は別のまとまりに保留する。
- FR-005: 通常縦画面412×924dp、小画面、横持ち、大きい文字で空状態の操作とフッターに到達できる。
- FR-006: 権限の判定・要求、一覧取得、キャンセル、選択、外部viewer/Files、保存・現像の所有関係を変えない。

## Edge Cases
写真のみ・動画のみの全面許可と選択許可の組合せ、古いAndroid、0件、読込中0件、読込中既存タイルあり、追加読込、試験注意展開、長いフォルダ名、大きい文字・狭い高さ。

## Success Criteria
- SC-001: 全面許可・選択のみ・混合許可・未許可・非対応の案内を区別し、誤った全面許可を示さない。
- SC-002: 空状態の2操作は有効時1回のタップでそれぞれ対応する操作だけを1回呼び、無効時は呼ばない。
- SC-003: 通常・小画面・横長・文字倍率1.3の合成画面で案内と操作へ到達できる。実機確認は別途未確認とする。

## Scope / Assumptions
現像の追加修正は044に分離。全選択UIの再設計、スクロール閾値の一律統一、権限追加、外部素材、実機操作、Releaseは対象外。新しい仕様判断はない。権限未許可でもアプリ所有の撮影物が見える既存契約を維持する。
