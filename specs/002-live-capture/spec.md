## User Scenarios & Testing

各storyのPriorityは本仕様内の優先度であり、開発フェーズの番号ではない。
現行P0の受入条件・実測結果をこの仕様で合格へ変更しない。

### User Story 1 - ライブで撮影機会を逃さず記録する (Priority: P1)

撮影者は暗いライブハウスで、動くパフォーマーを静止画・動画で撮影する。
STILL/CINEを同じ撮影体験の中でワンタップで切り替え、モードに適切な露出設定を使う。

**Why this priority**: 最優先用途はアイドルのライブパフォーマンスの静止画・動画記録。
風景・街並み・ポートレートより、暗所・動体・照明・音声・応答性の成立を先に確かめる。

**Independent Test**: 同一場面で静止画→動画→静止画を切り替え、保存・露出・音声・復帰の結果と待機時間を確認する。

**Acceptance Scenarios**:

1. **Given** STILLで撮影可能、**When** CINEへ1回の操作で切り替える、**Then** 録画状態とfps・
   シャッター時間または角度・音声状態が分かり、対応していない条件は理由を確認できる。
2. **Given** モードごとに異なるISO/シャッター設定、**When** 往復切替する、**Then** 各モードの
   有効な設定を復元し、静止画の長い露光を無条件に動画へ引き継がない。
3. **Given** 切替中、**When** 同じ被写体を追う、**Then** 構図とプレビューの維持を目指し、
   維持できない画角差・待機・ブラックアウトを測定結果と制約として確認できる。
4. **Given** 録画・復帰・停止、**When** 収録を完了する、**Then** 音声有無と成功/失敗が明示され、
   再生可能な素材だけを完了扱いにし、既存の静止画保存を損なわない。

### User Story 2 - Stage Clearで人物と照明を美しく残す (Priority: P1)

撮影者はライブ写真の肌を明るく白く透明感のある印象に整えつつ、肌の質感・立体感と会場の照明を残す。

**Why this priority**: 初期ルックの中でStage Clearの画質を最も優先し、プリセットの数より完成度を重視する。

**Independent Test**: 同じ元データから基準処理とStage Clearを比較し、赤・青・マゼンタ等の照明別に肌と階調を評価する。

**Acceptance Scenarios**:

1. **Given** 暗所・高ISOの人物素材、**When** Stage Clearを適用する、**Then** 赤み・黄ばみ・濁り、
   中間調、自然なノイズ、肌ディテール・立体感を比較できる。単なる露出上げや一律の白塗りにしない。
2. **Given** 強いスポット・逆光・色照明、**When** 処理結果を比較する、**Then** 柔らかなハイライトと
   照明の雰囲気を評価し、元データで飽和したチャンネルの情報復元は保証しない。
3. **Given** 初期プリセット、**When** ルック・最小限の強度を切り替える、**Then** 元素材から別の結果を
   再書き出しできる。詳細エディターやユーザープリセット登録を前提にしない。

### User Story 3 - 元の構図を残し、後から仕上げる (Priority: P2)

ライブでは元の画角・解像度・RAWを可能な限り保ち、被写体を切り落とさずに記録する。
風景・ポートレートでは映画的な横長構図も楽しむ。

**Why this priority**: ライブでの撮影時横長固定を避け、原本から再編集できることを優先する。

**Independent Test**: 同じ原本から複数比率の出力を作り、元へ戻して再フレーミングできることを確認する。

**Acceptance Scenarios**:

1. **Given** ライブ撮影、**When** 保存する、**Then** 撮影時の横長クロップを必須にせず、
   可能な記録範囲・解像度を維持し、原本と編集設定を分離する。
2. **Given** 原本、**When** 4:5・1:1・3:2・16:9・21:9へ変更する、**Then** 非破壊で変更・解除・再書き出しできる。
3. **Given** 風景/ポートレート、**When** 21:9または2.39:1の構図ガイドを使う、**Then** 原本を保ち、
   後から再フレーミングできる。プレビュー比率と記録比率を混同しない。

### User Story 4 - 少数のルックを写真・動画で使い分ける (Priority: P2)

撮影者はStage Clear、Stage Dramatic、Cinema T&Oを選び、写真と動画で一貫した色の意図を再利用する。

**Independent Test**: 同じ照明/被写体の静止画と動画でルックと強度を揃え、色・階調の差を比較する。

**Acceptance Scenarios**:

1. **Given** 初期3ルック、**When** 切り替える、**Then** Stage Clearは肌・透明感、
   Stage Dramaticは強い黒/光影/逆光/照明色、Cinema T&Oは青緑の暗部/暖かな明部/映画的階調という意図を区別できる。
2. **Given** 写真と動画、**When** 同じルックを使う、**Then** 入力の違いを考慮した結果を比較でき、
   同じパラメータだから同じ画になるとは扱わない。
3. **Given** 撮影UI/アイコン案、**When** デザインを決める、**Then** 無機質・メカ感を共通軸とする
   複数案を比較してユーザーが最終選択する。LIVE/SCENEは比較対象の案であり、独立モードとして固定しない。

### Edge Cases

- RAW+JPEG/動画の出力組合せが使えない、mode別設定の範囲が違う、切替で画角/プレビューが変わる。
- 動体AFの迷い・背景への抜け、強い逆光、赤/青/紫/マゼンタの飽和、暗部ノイズと質感の衝突。
- LEDの周期によるフリッカー/バンディング、動画のフレーム周期と露出時間の衝突。
- 音声拒否・無音・録音エラー・音割れ、保存/Finalize失敗、発熱・性能低下・背景復帰。
- ルック変更で原本が上書きされる、表示ガイドと保存クロップの取り違え、写真/動画の色空間不一致。
- 共有ギャラリーのDNG非対応、元から失われたハイライト/色情報の復元要求。

### Key Entities

- **原本素材**: 形式、記録範囲/解像度、入力色空間、撮影条件、検証用識別子。個人写真を公開資料にしない。
- **mode別撮影設定**: STILL/CINE、ISO、シャッター時間/角度、fps、WB、focus/AE/音声状態、対応範囲。
- **ルック定義**: 名前、版、最小強度、入力変換/トーン/色の意図、適用先。ユーザー詳細編集は後続。
- **編集定義**: 原本参照、ルック版/強度、非破壊crop、出力比率。原本を書き換えない。
- **評価記録**: 条件、指定/実測、比較対象、成功/制約/非対応、再現手順、ユーザー報告と原本確認の区別。

## Assumptions

- ここで定めるのは製品の方向と後続の受入軸。現在のアプリに動画・RAW現像・ルック・編集UIがあるとは扱わない。
- 最初の対象はPixel 9a、端末内処理、バックエンドなし。既存カメラ基盤・保存方式を維持する。
- 参考思想はChromagraph CameraのRAW/ルック、SIGMA fpのSTILL/CINE/色、GRの即写性。
  完全な再現・互換性を約束するものではない。
- 定量の最終合格閾値はP0.5のbaseline測定後、調整前に固定する。実測限界を隠すために変更しない。
- 実機未確認は合格へ変更せず、合意した範囲の次の限定作業を停止する唯一の理由にも使わない。
  自動検証・独立レビューと、残る実機確認を分けて管理する。
- [plan.md](plan.md)の試行回数・サンプル構成は初回検証の提案であり、実測結果や実装許可ではない。
