# Feature Specification: RAW撮影後の保全と自動現像

**Feature Branch**: `docs/030-raw-save-auto-develop`

**Created**: 2026-11-04

**Status**: Draft・設計のみ。merge前は現行保存経路を変更しない。

**Input**: DNGは共有領域の1つを永続原本として編集・現像から参照し、恒久的な二重保存を避ける。
撮影優先、DNG非破壊、仮JPEGは内部のみ、現像成功後のJPEGを共有カメラロールへ公開する合意を維持する。
関連: [保存専用Issue #89](https://github.com/reitojike/cinematic-camera/issues/89)、
[#78](https://github.com/reitojike/cinematic-camera/issues/78)、[014 handoff](../014-stage-clear-v1/handoff.md)。
既存Issueの範囲を拡大した扱いにはしない。

## User Scenarios & Testing

### User Story 1 - 撮影物を失わず次の撮影へ戻る (Priority: P1)

撮影者はRAW原本を残し、現像の完了を待たず次の撮影へ進める。

**Independent Test**: 成功・形式別部分成功・保存失敗・中断を与え、受領済み原本と仮JPEGのバイト列、公開対象、撮影状態を確認する。

**Acceptance Scenarios**:

1. **Given** RAW+JPEG撮影、**When** 各ファイルを受領、**Then** DNGは原本として保全し、仮JPEGは共有画像へ出さない。
2. **Given** 片方の形式だけ成功、**When** 他方が失敗・中断、**Then** 成功分を失わず、不足と有効性未確認を示す。
3. **Given** 旧版の共有JPEG/DNG/MP4、**When** 新しい保存方式を使用、**Then** 旧写真を移動・上書き・削除しない。
4. **Given** 完全な共有DNGを確認できた撮影、**When** 保存の後処理を完了、**Then** 内部の一時DNGを解放し、共有DNGだけを永続原本とする。

### User Story 2 - 余裕がある間に現像済み写真を得る (Priority: P2)

撮影者は手動現像を必須にせず、処理可能な間に現像済みJPEGをカメラロールで受け取る。

**Independent Test**: 撮影・録画・熱・処理能力・foreground状態を切り替え、新規処理の可否と停止、再開、公開結果を確認する。

**Acceptance Scenarios**:

1. **Given** 撮影が優先される状態、**When** 現像要求が増加、**Then** 重い処理を開始せず、原本参照だけを保留する。
2. **Given** 処理が許可された状態、**When** 現像成功、**Then** 完全なJPEGを共有カメラロールへ1件だけ公開する。
3. **Given** 現像/公開中に中断、**When** 再開、**Then** 原本と仮JPEGを保ち、公開済みか不明な出力を自動で増殖させない。
4. **Given** 再インストールや原本の外部移動、**When** 元の参照で開けない、**Then** 原本を選び直して再検証でき、失われた編集設定を復元済みと表示しない。

### Edge Cases

- RAWのみ/JPEGのみ対応、callback順序逆転・重複・遅延・片方欠落。
- 容量不足、close/台帳書込み/共有保存失敗、process death、OSによるpending画像の除去。
- 公開commit成功後の応答喪失、一時DNG削除前後の中断、共有DNGの外部削除・移動・同サイズ改変、権限やvolumeの変化。
- 再インストール/データ消去で参照許可と編集情報が失われる。DNGがギャラリーや選択画面に出ない。
- 新しい撮影、録画/Finalize、背景化、非協調的decode、端末発熱、未知の実測性能。

## Requirements

- **FR-001**: 完了を確認したDNG/仮JPEGは、現像の失敗・中断・再起動で失わない。内部の一時DNGはFR-003の共有原本への引渡し確認後だけ削除できる。未完了ファイルを有効原本と表示しない。
- **FR-002**: RAW撮影時の仮JPEGはアプリ内部の永続領域だけに保存する。通常のJPEG単独撮影と動画の共有保存は維持する。
- **FR-003**: DNGの保存先は現行の`Pictures/Cinematic Camera/`を維持し、共有DNGの1つを唯一の永続原本とする。共有先の全バイト一致・読取り可・公開済み・台帳記録を確認してから内部の一時DNGを削除する。共有保存失敗/不明/照合失敗時は一時DNGを保全し、成功扱いにしない。
- **FR-004**: 現像成功・出力検査・書込み完了後のJPEGだけを共有公開する。DNGの共有保存とJPEG公開は別の成功状態とする。
- **FR-005**: 画像の重い処理は撮影経路で実行しない。停止要求で撮影の受付を待たせず、応答性を保証できない処理はカメラ使用中に開始しない。
- **FR-006**: 原本参照・処理定義・処理世代・公開状態を永続化し、旧処理の完了で新しい定義や公開状態を上書きしない。
- **FR-007**: 再開時は同じ公開操作を照合する。既に公開済みの行を再作成・上書き・rollback削除せず、判断できなければ不明として停止する。
- **FR-008**: 既存写真と別撮影の出力を移動・削除しない。新しい広範囲ストレージ権限やバックエンドを導入しない。
- **FR-009**: Stage Clear v1の版・強度（初期0.5）と外部決定の露出を処理ごとに固定する。画素処理は#78、顔/露出は#79、編集UIは#81の責務とする。
- **FR-010**: 編集・現像は共有原本を読み取り専用で参照し、恒久的な再コピーを作らない。処理開始・公開直前の検証で原本の消失/アクセス拒否/内容変化を検知したら、その処理・出力公開を止め、同名ファイルへ自動で付け替えない。
- **FR-011**: 再インストール後は以前のアクセス権を前提とせず、標準の写真/ファイル選択で本人が選んだDNGの参照許可を取得・検証する。内部の編集情報はデータ消去等で失われ、DNGだけから過去の設定を復元できるとは保証しない。
- **FR-012**: DNGと現像JPEGは別の共有画像である。他アプリでの二重表示やDNG描画・選択可否は制御/保証せず、実機で確認する。非表示化のために原本を移動・削除しない。

### Key Entities

- **撮影記録**: 撮影ID、形式別受領状態、一時DNG/内部JPEG参照、共有DNGへの引渡し状態。
- **原本参照**: 共有URI、原本のサイズ/内容識別、参照許可の由来と利用可否。編集定義とは分離する。
- **現像要求**: 原本参照、固定した処理定義、世代、処理/停止状態。要求は画像バッファを保持しない。
- **公開記録**: 現像結果またはDNGを識別する操作ID、出力参照、共有行と公開状態。

## Success Criteria

- **SC-001**: [検証表](quickstart.md)のアプリ内故障点で、少なくとも一方の確認済みDNGコピーと仮JPEGのハッシュが不変、仮JPEGの共有公開件数が0となる。引渡し成功後の後処理で、内部DNGは0件、共有DNGは1件となる。
- **SC-002**: 同一公開操作を繰り返し復旧しても完成JPEGは最大1件。不明状態では新しい行を作らず保全する。
- **SC-003**: 撮影/録画/停止要求/不明な性能の状態では新規重処理の開始が0件、処理の完了待ちが撮影受付の条件にならない。
- **SC-004**: Pixel 9aで現像無効/有効時の撮影受付、preview周期、保存、熱、ピークメモリを比較し、許容差を有効化前に固定できる。未測定時はカメラ使用中の現像を無効に保つ。
- **SC-005**: 処理開始・公開直前の検証で原本不在・同サイズ改変・アクセス失効を検知したattemptからの公開は0件。選び直し後の同一性確認と、編集情報が失われた場合の再編集開始を区別できる。

## Assumptions

- DNGの公開範囲は現行どおり。今回変更する公開対象はRAW撮影に付属するJPEG。既存写真の移行は行わない。
- 最初はカメラを使っていないforeground中だけ自動処理候補にする。背景service/WorkManagerは先行追加しない。
- 内部領域はアンインストール/データ消去で失われる。永続化はこの範囲を越えたバックアップ保証ではない。
- 共有原本への引渡し前にアンインストール/データ消去された一時DNGは保全できない。共有後も他アプリや本人による削除・破損を防げる設計ではない。
- 原本照合とJPEG公開は外部操作に対して原子的ではない。最終照合後に外部変更が起きた場合、検知前の公開を排除する保証はない。
- 写真選択・再関連付けのUI実装は後続。今回定義する参照許可/検証契約は、その実装済み宣言ではない。
- この設計だけでDNG decode・現像・実機性能が成立したとは扱わない。
