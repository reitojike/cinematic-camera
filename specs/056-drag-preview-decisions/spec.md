# 写真単位の判定共有とドラッグ中縮小preview

関連: Issue #220。状態: Draft。mergeは本人の個別承認待ち。

## 利用者シナリオ

### US1: 既定の画素出力を変えずに判定を共有する（P1）
正確な1024px処理で得た自動判定を同じ写真の縮小previewへ渡せる。指定しない呼出は従来の計算と完全一致する。
- Mistの最初の自動強度、顔cut係数、cut後再処理の自動強度を区別して保持する。
- 判定の取得/受渡し入口だけを変更する。各画素・行ループ、式、丸め、パラメータ、golden、保存出力は変更しない。
- 未指定呼出と従来計算のraw-bit一致、同サイズで取得→再使用した一致を確認する。

### US2: ドラッグ中は256px、確定後は1024px（P1）
- 手動編集の強度/色温度/明るさのドラッグ中、同じ処理の長辺256px以下を表示する。
- 同じ写真で最後に完了した長辺1024px以下の正確な処理の判定値を使用する。色温度/明るさ操作中の値が少し古いことは近似として許容する。
- 正確な判定がまだない場合は判定を新たに縮小像で決めず、既存表示を維持する。
- 指を離すと最新の確定値で正確に処理し、表示と判定を更新する。旧粗表示は新しい確定像を上書きしない。
- 同時処理は1件、待機は最新1件。ドラッグ値を保存設定やsave handleへ昇格させない。
- 写真切替、編集終了、背景化、メモリ通知、取消/失敗で他の写真や終了済ownerの結果を採用しない。Bitmapを回収する。

### US3: preview/保存の判定差を測る（P2）
同じ合成sceneの1024pxと原寸で自動判定値を記録する。既存の原寸stage callbackを用い、保存工程は変更しない。判定の差と最終画像の差を同じ証拠とせず、見た目への影響の可能性と未確認範囲を区別する。

## 受入・範囲
- API未指定、顔cut再処理、各強度、取消、同サイズoverrideの合成回帰。
- 最新待機/古い結果拒否、release確定優先、写真切替/終了、256と1024の判定共有、設定永続化の非変更。
- 1024対原寸の測定は合成のみ。実機・実写真・録画・撮影情報を使用しない。
- lint/unit/assemble、Android合成、最終head CI、canonical/独立レビュー。実機性能・touch-to-photon・主観画質は未確認として残す。
- #208の第1段階実機確認と今回の合成検証は別。0.05秒/0.5秒の目標を完了の条件にしない。

## 停止条件
画素式/行ループ/golden/保存の変更、原本/取消/所有者契約の破壊、検証失敗、想定2PR超過が必要なら停止。API入口の判定共有は今回承認された範囲。UIを含むmergeは個別許可まで行わない。
