# Feature Specification: v15撮影画面フィードバック修正

**Feature Branch**: `012-v15-capture-feedback`
**Created**: 2026-11-03
**Status**: Draft
**Input**: [Issue #47 の追加受入条件](https://github.com/reitojike/cinematic-camera/issues/47#issuecomment-6592453274)。v15の既存案内4点の確認と、今回の6件の不具合の解消は別に扱う。

## User Scenarios & Testing

### User Story 1 - 露出の主値を読み違えず撮影する (Priority: P1)

撮影者はAUTOの有効な実測を途切れず読み、MANUALでは最後に選んだ撮影設定を確認する。
**Why this priority**: 補償プレビューの明るさと撮影設定を取り違えないため。
**Independent Test**: 正常・欠落・不正・別用途の観測、2秒境界、世代変更、送信中の設定変更を順に与え、表示と撮影設定の独立性を確認する。
**Acceptance Scenarios**:

1. **Given** 同じ世代の正常なAUTOプレビュー実測、**When** 後続の観測が欠落・不正・静止画用途、**Then** 元の取得時刻から2000ms以内の正常値を保ち、不要な「—」のちらつきを出さない。新しい正常値で更新する。
2. **Given** 値の取得後2000msちょうど、**When** 主値を見る、**Then** まだ有効。2000msを超えた場合・世代変更・接続解除では旧値を使わず「—」にする。欠落観測で取得時刻を延長しない。
3. **Given** MANUALで撮影targetを変更、**When** 受付待ちや補償プレビュー実測が届く、**Then** ISO/SS主値は最新の有効な撮影targetを示し、古い受付値や補償実測に置き換えない。AUTO主値は近似実測と明示する。
4. **Given** RAW検証の固定target、**When** 表示・観測・世代が変わる、**Then** 固定targetと世代検査を維持し、丸め表示や補償値を撮影ISOへ書き戻さない。補償の詳細は診断で確認する。

### User Story 2 - シャッター状態を大きさと色で見分ける (Priority: P1)

撮影者はSTILLの白い内円と、ひと回り小さいCINE待機の白い内円を見分ける。
**Why this priority**: 待機と実録画の誤認を避けるため。
**Independent Test**: STILL/CINEと全録画段階で内円寸法・色・操作領域・読み上げを比較する。
**Acceptance Scenarios**:

1. **Given** 待機、**When** シャッターを見る、**Then** STILL内円は58dp、CINE内円は48dpで、外周の操作領域と読み上げを維持する。
2. **Given** STARTING/RECORDING/STOPPING/保存/失敗、**When** 状態変化、**Then** 実RECORDINGのみ赤。停止・復旧操作と状態バーへの進捗集約を維持する。

### User Story 3 - 各目盛りを同じ感触で選ぶ (Priority: P1)

撮影者はISO/SS/EV/WB/MFを共通の距離蓄積式目盛りで選び、値が変わった時だけ軽い触覚応答を受ける。
**Why this priority**: 操作ごとの不一致を減らし、送信中の誤操作を防ぐため。
**Independent Test**: drag/tap/矢印/読み上げ、同値・端点・無効・送信中を照合し、EV/WB即時操作とMF適用/取消を個別確認する。
**Acceptance Scenarios**:

1. **Given** 有効な目盛り、**When** 距離が蓄積して実際の段が変わる、**Then** 共通の選択経路を使い触覚応答を要求する。同値・端点・無効・送信拒否では要求しない。端末の触覚設定を尊重する。
2. **Given** EV/WB、**When** 選択を送信中、**Then** 同時に1要求だけとする既存契約を守り、適用ボタンを追加しない。MANUALに未対応EVを追加しない。
3. **Given** MF、**When** 段を選択し適用/取消、**Then** draftを編集してから適用する既存契約を維持する。端末が報告した最大値を100等分するUI候補はハードウェアの離散能力を示さない。既存の正確な選択値を保持し、表示丸めを送信値にしない。

### User Story 4 - Androidの回転設定に合わせて表示を読む (Priority: P1)

撮影者は自動回転OFFでは縦向き表示、ONでは物理向きに追従する要素表示を使う。
**Why this priority**: ユーザーが選んだ端末設定を撮影UIへ反映するため。
**Independent Test**: OFF/ON×0/90/180/270度、使用途中の設定切替、背景化/復帰を確認し、撮影出力の向きも独立に比較する。
**Acceptance Scenarios**:

1. **Given** 自動回転OFF、**When** 端末を4方向へ持ち替える、**Then** 要素は縦向きのまま。ONでは物理向きへ最短経路で追従し、固定配置・プレビュー寸法を保つ。
2. **Given** 使用途中の設定切替または復帰、**When** 最新設定を読む、**Then** 次の物理移動を待たず表示へ反映する。設定は読み取りだけとし、追加権限を要求しない。
3. **Given** 静止画撮影/録画開始、**When** 表示が縦固定または端末を回転、**Then** 出力方向は物理向きから決める。録画出力方向は開始時に固定し、録画を継続する。

### Edge Cases

ISOのみ/SSのみ欠落、無効値、表示へ渡す時刻が負/未来の場合の拒否、正常値なし、STILL_CAPTURE/UNKNOWN観測、旧世代観測、2秒境界、AUTO/MANUAL切替、RAW固定target、古い受付応答、複数段drag・逆方向・端点、触覚無効、MF非候補の正確な既存値、EV/WB busy、180度回転、向き不明、設定途中切替、背景化/復帰を扱う。

## Requirements

### Functional Requirements

- **FR-001**: AUTOのISO/SS主値は現世代の有効なプレビュー系実測を軸ごとに保持し、欠落・不正・別用途観測で正常値を消さない。正常値を取得した元の時刻から2000ms以内だけ有効とし、古い世代・切断・期限超過は「—」。再利用で時刻を延長しない。
- **FR-002**: AUTO主値は標準候補への近似実測、MANUAL主値は最新の有効な撮影targetと明示する。補償プレビューは診断の実測として区別し、表示丸め・保持値・補償ISOを撮影設定へ書き戻さない。RAW固定targetと世代制約を維持する。
- **FR-003**: 待機内円はSTILL 58dp/CINE 48dpとし、外周操作領域・読み上げを維持する。実RECORDINGのみ赤とし、開始中・停止中・保存中を実録画に見せない。既存の停止/復旧と状態バーを維持する。
- **FR-004**: ISO/SS/EV/WB/MFのdragは距離蓄積式detentを共用し、tap/矢印/読み上げも同じ選択actionへ接続する。実段変更時だけ標準の軽い触覚応答を要求し、同値・端点・無効・拒否時には要求しない。
- **FR-005**: EV/WBは即時反映と同時1要求のbusy guardを維持する。MFはdraft/適用/取消と正確な既存選択値を維持する。MFの報告最大値100等分はUI候補としてのみ扱い、端末の離散能力を主張せず、表示丸めを書き戻さない。
- **FR-006**: UI要素はAndroid自動回転OFFで縦向き、ONで物理4方向へ追従する。設定を読み取り、途中切替・復帰に反映する。固定配置・プレビュー寸法を保ち、権限追加や端末設定の変更をしない。
- **FR-007**: 撮影出力はUI回転設定から独立した物理向きで決定し、録画開始後は出力方向を固定する。録画継続・overlay・Back・RAW/保存の既存契約を後退させない。
- **FR-008**: 対象は上記6件の不具合に限定する。camera設定方式・RAWツール・GPU・新ギャラリー・依存・署名/Secrets・他リポジトリを変更しない。機械確認と実機ACを分け、6件は実機確認まで解決扱いにしない。merge/Releaseは別途承認を要する。

### Key Entities

軸別正常実測slot（世代・用途・元取得時刻・値）、AUTO近似実測/最新MANUAL撮影target、固定RAW target、共通目盛りの選択index/距離残量、MFの正確なdraft、即時操作busy、自動回転設定、独立した物理向き/UI向き/録画開始出力方向。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 同世代の正常値に続く欠落/不正/別用途観測で2000ms以内の不要空白0件、期限超過/旧世代値の主値採用0件、表示から撮影設定への書戻し0件。
- **SC-002**: 待機58/48dpと全録画段階の状態表が一致し、実録画以外の赤表示0件、操作領域・読み上げ・停止/復旧の欠落0件。
- **SC-003**: 5項目×drag/tap/矢印/読み上げの選択経路が一致し、同値/端点/無効/busyで誤触覚0件、EV/WB同時要求超過0件、MF適用/取消と正確な値の回帰0件。
- **SC-004**: 自動回転2設定×4方向と途中切替/復帰で表示方針が一致し、UI設定による出力方向の誤変更0件。録画は持ち替え前後で1本として完了する。
- **SC-005**: 最新headでunit/lint/build、差分・公開情報検査、必須CI、独立/canonicalレビュー、未解決会話0件を確認する。実機の6件は別の未完了ACとして維持し、既存v15案内の確認を流用しない。

## Assumptions

本Draftの採用時、[009 FR-010/US2](../009-capture-ui-states/spec.md)の「常時preview実測を主値」はFR-001/002へ、[003 US3/FR-007](../003-capture-ui/spec.md)の「常時物理向きへUI回転」はFR-006/007へ明示的に置換する。他の契約は維持し、merge前にmainの契約が変更済みとは扱わない。追加質問が必要な仕様未決事項はない。実機・暗所可読性・体感の結果は未確認とする。
