# Feature Specification: Stage Clear Android移植の最初の縦切り

**Issue**: [#78](https://github.com/reitojike/cinematic-camera/issues/78)
**Status**: 提案。#78全体の完了ではない。
**Input**: [PC基準の引き継ぎ](../014-stage-clear-v1/handoff.md)、同spec/plan、PCコード。

## User Story / Acceptance

移植担当者は、写真を公開せずにPCとAndroid用Kotlinの保護処理を同じ合成入力で比較できる。
顔の赤み抑制→顔の白飛び判定→必要時の前段再計算→ハイライト処理を全画素で検証する。

- **FR-001**: `stage-clear-v1`、既定強度0.5、保護用定数・行列をPCの正本から生成し、Kotlinと共有する。PCの処理・版・既存goldenを変えない。
- **FR-002**: 入力は行優先RGB Float32の線形sRGB/D65。負値・1超を保持し、転送関数を二重適用しない。顔マスクは同じ寸法の0〜1。空・不正寸法・非有限値・不正マスクを拒否し、入力を変更しない。
- **FR-003**: PCの`skin_chroma_cap`（選択S、vivid=.24）、`face_cut`、`shoulder`を純Kotlinへ移植する。強度を保護処理へ掛けない。顔はマスクとして受け取り、検出器は含めない。
- **FR-004**: 顔減光が必要ならglowed入力を係数倍し、呼出側の段2〜5を再実行してから段6と8を適用する。初回出力を単に暗くする近似にしない。
- **FR-005**: 合成goldenを正本から再生成でき、全画素・係数・再計算回数・入力保持を検証する。既存の領域平均goldenを全画素やDNG経路の証明としない。
- **FR-006**: 撮影・保存へ接続せず、原本に触れない。DNG変換、R7土台、雰囲気段1〜5、顔検出、端末実測は後続として区別する。

## Success Criteria

- **SC-001**: Kotlinが合成全画素の絶対誤差2e-5以内、顔係数2e-6以内でPCに一致する。CPU float行列とNumPyの丸め差を許す暫定境界で、画質の閾値ではない。
- **SC-002**: 黒・負値・1超・色光・赤い顔・顔なし・49/50画素境界・0.5のマスク境界・90百分位の補間・最大0.7EVを検証する。
- **SC-003**: Android lint/unit/build、PC合成検証、独立レビューを実施し、実機未検証と#78の残件をPRへ明記する。mergeは別承認。

## v1の互換制約

顔の百分位はマスク全体で計算するため、小さい明るい顔が他の顔に埋もれることがある。
縮小後に`faces > .5`が50画素未満なら減光しない。最大0.7EVの減光と前段再実行は、最終輝度0.90以下を保証しない。
これらを互換テストで固定し、顔ごとの判定等の変更は将来の版として検討する。

## 停止条件

正本の処理順やパラメータ変更が必要なら止めて版の変更を提案する。未検証の実機画質・性能は合格にしない。
