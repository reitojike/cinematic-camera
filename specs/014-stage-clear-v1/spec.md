# Feature Specification: Stage Clear v1（PC基準の定義）

**Feature Branch**: `feat/028-stage-clear-v1`
**Created**: 2026-11-04
**Status**: 確定（Issue #77）。PC基準実装と合成テストまで。Android移植・preview・編集UIは後続。
**Input**: [Issue #77](https://github.com/reitojike/cinematic-camera/issues/77)、[002 US2](../002-live-capture/spec.md)、
PC RAWの第7回〜第11回でユーザーが比較選択した結果。

## User Scenarios & Testing

### User Story 1 - 撮って出しで照明に浸る人物写真にする (Priority: P1)

撮影者はRAWから、照明の色に浸りつつ光がにじむ夢っぽさを持ち、顔の赤みや白飛びが抑えられた写真を自動で得る。

**Independent Test**: 同じ原本・同じ露出で基準処理とStage Clear強度0/0.5/1を照明条件別に並べ、
強度1が確定形と一致し、強度で雰囲気だけが変わることを比べる。

**Acceptance Scenarios**:

1. **Given** RAW原本と顔の範囲、**When** 既定の強度でStage Clearをかける、**Then** 第10回で決めた最終形になる。
2. **Given** 同じ原本と露出、**When** 強度を0/0.5/1に変える、**Then** にじみ・ミスト・周辺減光・彩度だけが変わり、
   顔の赤みの抑え・顔の白飛びガード・ハイライトのなだらかさはどの強度でもかかる。
3. **Given** 赤・青・紫/マゼンタの照明、**When** Stage Clearをかける、**Then** 照明の色を中立へ戻さない。

### User Story 2 - 写真ごとに強さを下げられる (Priority: P3で実装)

撮影者は編集画面で、写真ごとに強度を0〜1の間で下げられる。原本と編集情報は分けて持ち、原本は書き換えない。

### Edge Cases

- 顔が検出されない（マイク・髪で隠れる、横顔）: 顔の処理はかからず、画面全体の処理だけになる。写真ごとの手動調整で補う。
- 顔以外の肌（腕・脚）の赤み: 扱わない。
- RAWで既に飽和したチャンネル: 元情報は戻らない。白飛びは現像で起きる分を抑えるだけ。
- 明るい写真（白に近い面積が大きい）: 光を足す処理（ミスト・Orton）を自動で最大半分まで弱める。

## Requirements

- **FR-001**: Stage Clear v1は第7回の色の土台の上に、にじみ、アイコニック層、顔の赤みの抑え、顔の白飛びガード、
  ハイライトのなだらかさを決めた順でかける。処理順とパラメータは[plan.md](plan.md)に従う。
- **FR-002**: 強度は0〜1の連続値とし、既定は1。強度はにじみ・ブラックミスト・Orton・周辺減光・彩度に掛ける。
  範囲外の強度は受け付けない。
- **FR-003**: 顔の赤みの抑え、顔の白飛びガード、ハイライトのなだらかさは保護の処理として強度によらずかける。
- **FR-004**: 顔の範囲は外部の顔検出から受け取る（PCはYuNet、AndroidはML Kit等を想定）。検出器を処理本体に含めない。
- **FR-005**: 露出はStage Clearに含めない。比較では基準処理と同じ露出に揃え、ルックと一緒に露出を変えて良く見せない。
- **FR-006**: 合成画像の入力から強度別の期待値（golden）を持ち、CIで処理の意図しない変化を検出する。
- **FR-007**: 版を`stage-clear-v1`として識別し、処理やパラメータを変えるときは新しい版にする。

## Key Entities

- **ルック定義**: 名前Stage Clear、版`stage-clear-v1`、強度0〜1（既定1）、処理順とパラメータ。
- **顔の範囲**: 画像と同じ大きさの0〜1のマスク。検出結果から作る。
- **編集定義（P3）**: 原本参照、ルック版、写真ごとの強度、手動の色温度・明るさ。

## Success Criteria

- **SC-001**: 強度1の出力が第10回の確定形と数値的に一致する（合成テスト）。
- **SC-002**: 強度0/0.5/1で光の広がりが単調に増え、強度0では光を足さない（合成テスト）。
- **SC-003**: 強度0でも顔の白飛びガードとハイライトのなだらかさが働く（合成テスト）。
- **SC-004**: 照明条件別（中立光・赤・青・紫/マゼンタ・スポット/逆光・手元で最も高いISO）の比較を、
  同じ原本・同じ露出で再生成でき、ユーザーが既定の強度を選べる。

## Assumptions

- PC実装はAndroid移植の基準で、処理時間や端末での見え方を保証しない。
- 比較素材は本人の非公開素材で、写真・撮影情報・写真ごとの数値はリポジトリに入れない。
- 暗い会場の高感度（ISO 6400以上）の人物素材と、本物のステージでのPixel 9a素材はまだない。
  Pixel 9aはモニタの色光を当てた室内の試し撮り（人物の顔なし）でだけ確認した。
