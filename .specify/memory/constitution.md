# Cinematic Camera Constitution

## Core Principles

### I. 合意した仕様と実測の追跡

ユーザーの合意したP0ブリーフを要件の根拠とし、機能別のspecで観測可能な振る舞いを、
planで技術設計を、tasksで作業と未確認事項を管理する。今後の機能変更は実装前に仕様を定める。
今回のSpec Kit導入は既存P0の合意内容を整理するもので、実装前に作成済みだったとは主張しない。
仕様・実装・実測が食い違う場合は差分と根拠を残す。

### II. Android標準APIを出発点にする

Android標準API、Jetpack、一般的なlifecycleと権限の扱いを優先する。標準から外れる必要が
実測された場合だけ、代案・理由・対象範囲をspecまたはplanへ記録する。CameraX管理の
CameraDevice / sessionを直接操作せず、独自回避やCamera2全面移行は合意なく進めない。

### III. 実装・受付・実測・合格を分ける

設定要求が受理されたこととセンサーへの反映、ファイルが保存されたこととDNGの有効性を
分けて記録する。ビルド、静的レビュー、エミュレーターの結果をPixel 9a実機の合格にしない。
未検証は未検証のままとし、端末非対応は実測した能力・エラー・再現条件で裏付ける。

### IV. ローカル保存と公開情報の境界

撮影物は合意した保存先で扱い、ログはアプリ専用領域に保持する。最新の合意では新しいJPEG/DNGを
標準MediaStoreの`Pictures/Cinematic Camera/`へ保存する。バックエンドを導入しない。
秘密、認証情報、署名秘密、個人情報、個人用絶対パス、撮影物、会話ログ、端末固有識別子を
リポジトリや配布ZIPへ入れない。要求されるカメラ能力やAndroidビルドの記録と、公開可能な
検証要約を区別する。サンプルに実ユーザー名や実端末の固有識別子を使わない。

### V. P0の最小範囲と適切な検証

P0はプレビュー、RAW、マニュアル露出の成立性を調べるために限定する。依存は必要なものだけ
固定版で導入し、今回指定されたCameraX 1.6.2を維持する。能力判定・値変換のunit testと
build / lint、実機の手動マトリクスを使い、検証のためだけの大規模GMDや製品機能を増やさない。

## 技術・公開上の制約

- Kotlin / Jetpack Composeと最小の単一app構成を使う。RAW現像、NDK、GPU/LUT、動画、
  21:9保存、SNS、ギャラリー、クラウドは別フェーズであり、今回実装済みとは扱わない。
- P0の完了判定と停止条件は機能specと`docs/P0_REPORT.md`で追跡する。実機AC3/4が
  不成立なら根拠付きBLOCKEDとして記録し、採否判断を勝手に補正しない。
- 署名秘密の新規生成・継続利用設定、Secrets登録、他projectの鍵の流用を無断で行わない。
  P0用の一時debug署名と、継続更新用の固定署名を混同しない。
- 公開範囲を変える前に、全Git履歴・branch・文書・workflow・配布物・公開されるログを検査する。
  問題が過去の履歴に残る場合、最新削除で解決扱いにせず、破壊的な履歴変更は相談する。

## 開発とレビュー

基本の流れはconstitutionを確認し、specify → clarify（必要時）→ plan → checklist（必要時）
→ tasks → analyze → implement → convergeとする。判断の重複文書は増やさず、既存レポートへ
リンクする。tasksの実装チェックと実機ACのチェックは別にする。

初回main初期化後は作業branchとDraft PRを使い、現在のheadのCI・レビュー・未解決会話を確認する。
利用者のmerge許可がなければmerge前に停止し、APPROVE代行、admin merge、チェック免除、
保護回避をしない。機械的検証は実際のAndroid workflowに合わせる。文書は原則日本語とする。

## Governance

本Constitutionは本リポジトリのspec、plan、実装、レビューへ適用する。ユーザーの明示指示と
作業範囲を優先し、衝突や未決事項を隠さない。改訂時は理由・影響・必要な移行をPRに記録する。
原則を壊す変更はMAJOR、新原則追加はMINOR、意味を変えない明確化はPATCHとする。
1.0.0はP0と公開・レビュー上の合意を初めて明文化した版。1.1.0はユーザーの追加要件に従い、
新撮影の共有画像保存を原則IVへ明記した。既存写真の移行・一括削除や新しい広範囲ストレージ権限は導入しない。
