# PR-C 表示レビュー資料

[表示指示書](DEVELOP_UI_REFACTOR_INSTRUCTIONS.md) の 3.4 (1)〜(4),(6) と、#382・#383 の本人レビュー指摘を対象とします。
基準は main `e9b4c75d`。本資料はレビュー準備中です。スクリーンショット取得・実行結果は未記入であり、合格の記録ではありません。

## 変更範囲

GPU の製品現像画面の表示のみです。CPU・診断経路、保存可否、取消、再開、照合、明示再保存の条件と状態遷移は変更しません。
PR-D 対象の画面全体の組み直し・CPU 引数削除は含みません。本人の表示承認前にはマージしません。

| 17-generic-failure-hold | 汎用問題カードと保存保留の chip。「一覧に戻る」以外の復旧・再試行操作を追加しない |

01〜12・15〜16 は実際の `PhotoRollDevelopView` に合成の表示状態を渡したものです。13〜14 は共通 `CaptureDialog` の表示 fixture です。
ダイアログ fixture は製品側の保存 owner に接続していないため、復旧の挙動試験を代替しません。

本人の追加指示に基づき、不正な PROBLEM / FAILURE バナーを本番で単に隠さず安全な汎用カードへ差し替える方針を追加しました。
17〜18 はその共通 policy の結果である正常な `developFailureFallback` を `ScreenMessages` に直接渡した表示 fixture です。
DEBUG 版で不正な `UiMessage` を作成しません。この2枚は本番版の不正メッセージ検出・差し替え処理を実行した証拠ではありません。
また HOLD は表示入力として維持されるだけで、実際の保存 owner の保全は別の試験・レビューで検証します。
18 は既存の `savingRecipe` 相当の可否入力により「一覧に戻る」が無効な場合を示し、fallback によって操作を有効化しません。
どちらも Android View ツリーのソフトウェア描画であり、実機 GPU 描画や画質の証明にはしません。

## 検証経過

- 初回 head `030b173`: ローカル `testDebugUnitTest` 1,357 件、失敗/エラー0、skip6。新規純粋表示12件はskip0で成功。`lintDebug` / `assembleDebug` / `assembleDebugAndroidTest` 成功。
- 同 head の CI は製品・Mesa・rawprobe・JNI 分離が成功。GPU/RAW 診断は共通 CaptureMessagesTest の strict/debug 前提で失敗しており、必須集約は未達。原因を共有部品担当と修正中。
- 独立静的レビューで、通知許可が保存バナーに隠れる問題と、取消済み写真の再開操作が別写真の保存バナーに隠れる問題を検出。通知は進捗バナーの副操作へ保持し、再開は表示選択後に重複する場合だけ省く修正を追加。保存/通知/再開の有効条件は変更しない。
- 追加回帰3件を含めた最終 head の実行結果、画像取得、本人表示承認は別途記録する。初回成功を最終版の合格へ読み替えない。
