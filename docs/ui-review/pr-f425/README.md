## 画面内比較

同じ端末・密度・文字倍率で、画面全体の「変更前 / 変更後 / 文言変更」を1ページに並べる。
カメラの映像のみ合成図形に置換。画面配置・テーマ・共通メッセージ・操作領域は各 commit の画面ソースを一時 androidTest に複写して描く。旧側のメッセージ組み立てと通知生成も旧版を使用する。

| 状態 | 変更前 → 変更後 | 注目点 |
|---|---|---|
| 権限なし | 従来の Text/TextButton → 共通 CENTER と「カメラを許可」 | 全文、折返し、ボタン、操作領域との重なり |
| 高温・通常 | WARNING のまま | 従来と同じ録画不可条件・黄色 |
| 高温・拒否直後 | WARNING → FAILURE「録画を開始できませんでした」 | 赤い失敗バナー。4秒後は通常 WARNING |
| 回転・通常 | 回転: 配置固定・文字のみ回転 → 画面の向きに合わせて文字だけ回転します。 | 下側通知が操作を隠さない |
| 回転・録画中 | 回転: 配置固定・文字のみ回転・録画継続 → 画面の向きに合わせて文字だけ回転します。録画は続いています。 | 長文の折返し |
| 設定変更中 | 設定変更中 → 設定を変更しています。 | 処理中バナーの配置 |
| 保存完了 | 保存しました（文言・緑色を維持） | 型によるトーン指定で変わらない |

合成表示では固定した通知や拒否状態を初期値に置く。これは実際の熱拒否イベント・録画・保存操作が成功した証拠ではない。カメラの初期化をしない。実写真・個人情報を使わない。
画面取得前に期待文言と probe 状態の不変を検査する。取得後に PNG を目視し、空白・途中描画・意図しない状態を除外する。全画面の上下を切り抜かない。

## Android 手動回帰（未実行）

AVD の使用枠を #290 担当と調整し、開始前に既存プロセスを確認する。Pixel は本人が利用可能なときの都度承認を待つ。人工的に実機を加熱しない。

1. 権限なしで起動し、CENTER の文言と［カメラを許可］を確認。押下で既存 OS 権限要求が出ること、拒否で画面が継続すること、許可後に既存プレビューへ進むこと。
2. 通常時に向きを変え、文字だけの回転・下側通知・4秒後の消去を確認。録画中版は録画可能な試験環境に限定し、録画停止などの挙動が変わらないことを確認。
3. 設定操作を行い、処理中表示→受付完了（緑）の文言、保存完了（緑）、その他の通知（通常色）を確認。ISO と SHUTTER の連結、長文、横向きの見切れを確認。
4. 合成入力による拒否イベントの Android 回帰を別に実行: 既存 startRecording の熱拒否分岐でカウンタが増えたときだけ FAILURE。約4秒後は WARNING。連続拒否では最後の拒否から4秒。再作成時に過去の拒否を再表示しない。
5. 高温を既に認識しているときは元からシャッターが無効。押せない操作を有効化したり、見た目試験のために録画受付条件を変えたりしない。実際の拒否分岐を通した試験と、固定表示 fixture は別に記録する。
6. 復旧中に Back を押したとき、既存 PROBLEM が残り、重複 TOAST が出ないこと。状態遷移・復旧ボタンの有効条件は変更前と同じ。

## 取得結果

- ATD API 37、1080×2424、density 2.625、fontScale 1.0、縦画面。7状態14枚。全取得試験1件成功、0失敗、0skip（ビルドを含む1分38秒）。代表3状態の preflight も成功。
- ソフトウェア Canvas に画面全体の decorView を描画。System UI、実 CameraX 映像、GPU、IME、動的回転は未確認。
- 同じ合成入力を両側へ設定し、期待文言と probe 状態の不変を assert。権限なしは未接続・撮影不可、録画中は合成 RECORDING/12秒。
- 高温拒否の画像は表示用状態の固定入力であり、startRecording の拒否分岐や4秒タイマーを実行した証拠ではない。
- 最初の preflight は試験専用の AVD 判定が ATD 名称を拾わず、取得前に停止。hardware=ranchu の標準エミュレーター判定を加え再実行。製品コードは変更していない。
- 最初の代表画像の点検で、権限なし fixture の接続状態を未接続へ修正し、全量は修正後に取り直した。初回の画像は掲載していない。

手動回帰は手順準備まで。実機の撮影・録画操作未確認を合成比較で代替したとは扱わない。本人の画面承認前にマージしない。
