# 線形入力と GPU 後段の切り分け（追加試験）

製品コード・FULL既定・保存経路・基準画像は変更していません。元の比較画像も更新していません。

## 条件

- 同じ5条件で full / half の入力寸法が一致することを確認。再リサイズなし。
- 両者へ full 側の写真解析（baseEV・centralP97）を渡し、手動EVも共通に固定。
- 線形入力、R7_FINAL、SHOULDER（表示用変換・JPEG圧縮より前）を比較。
- strength 0 と元のstrengthで比較。strength 0でもR7は動作する。
- 指標は無クリップの線形RGBの平均絶対差（MAE）。GPU自体のトーン処理を無効化した意味ではない。8bit表示指標や知覚距離とは直接比較できない。
- 入力段にはLibRaw展開と既存縮小の両方を含む。局所分位点・Mist自動強度は入力依存のままであり、全工程を固定した試験ではない。

02/05の大きな差は、GPUに入る前から存在します。色差（R−G / B−G）の誤差の平均も、入力時点で02は約0.215、05は約0.213です。JPEGや表示変換だけの問題ではなく、ルック強度を0にしても解消しません。R7後の差は増えますが、非線形変換・入力依存の局所解析を含むため「R7が何%悪化させた」とは算定しません。

03/04は全体平均が小さくても入力の最大差は約0.997 / 0.873あります。平均だけを理由に境界の局所差を合格扱いにはしません。

## 現実的な進め方（提案・未採用）

1. **既存LibRawで埋込JPEGを仮表示し、現行fullを一度だけ展開して置換**する方式を優先。初表示の待ちを減らせる可能性があり、編集・保存の画質は変えない。埋込JPEGは現像設定未反映と明示し、キャッシュは入替時に解放する。JPEGがない場合は既存経路へ戻す。編集可能になる時刻は短縮しない。
2. 編集可能までの短縮は、現行full経路のコピー・一時ファイルI/O・キャッシュ再利用等を工程別に計測してから、同一出力の改善を選ぶ。展開の二重実行を増やす half→full は優先しない。
3. halfへのぼかし・色差平滑化や軽量demosaicは、細部の喪失・保存との差を新たに作るため、品質維持が必要な代替としては未採用。後段パラメータ調整だけで入力段の差を回復できるとは考えない。

halfの採否は本人の目視と必要な実写確認による別判断です。この合成stress条件から、SIGMA実写での頻度・程度、Pixelの速度、埋込JPEGの解像度を推定しません。
