## 2. 優先順位と Codex の時間配分

Codex の稼働時間を節約し、dot で可能な調査・小規模実装・試験・レビュー・文書は dot が並列で進める。Codex が必要な実装は次の **v0.1.0 クリティカルパス**を優先する。独立した追加レーンは下記の明示範囲に限って先行し、競合時は #290 を優先する。

1. **#290 CPU・診断経路の削除**。1024px の GPU 全工程計測試験を通常の `androidTest` に移し、実際に実行されることを確認してから診断ビルドを削除する。
2. **初回表示改善（#233・#241）の製品接続**。#290 の安全な区切り後、JNI/build/入力 owner と画面の所有ファイルを確認して進める。PR-D・D1〜Dn との同時編集を避ける。安全性・表示切替・試験の設計を先に整理し、見た目の本人承認を得る。
3. **PR-D 現像画面の配置**。本人の見た目承認を得てからマージする。
4. **D1〜Dn の挙動不変リファクタリングと、GPU 基準画像比較の Mesa CI への移行**。
5. **実機での最終確認 → 本人承認 → v0.1.0**。正式タグ workflow 修正（2-10）は待ち依存から外し、追加レーンの #401 で完了した。

**PR-F は #290 の PR が CI・レビュー待ちの合間に進める。#290 と競合する場合は #290 を優先する。** PR-F を理由に上記の順序を逆転させない。

## 3. 承認のルール（重要）

### 承認なしで進めてよいもの
**計画どおりの作業で、プロダクトの機能や挙動に大きな変化がないもの**は、都度の承認を取らずに進め、結果を報告する。例：

- ブランチの push、Draft PR の作成、PR や Issue への記録（個人情報を含まないもの）、AVD の使用
- 試験・文書・CI の変更と、そのマージ
- 挙動を変えないリファクタリング（GPU 基準画像との回帰試験が通ることが条件）
- 検証用コード・旧文書・旧計測の削除（診断用ビルド・診断経路は次項の安全前提に従う）
- **CPU 版処理・診断経路の削除**（dev.4 のデザイン・通常編集〜現像・GPU 安定動作の本人確認後、CPU 版処理と診断経路それぞれの削除開始を本人が承認済み。GPU 回帰・定数正本・旧保存互換・共有部の分離・必要試験の移行などの前提を満たす範囲）
- 不具合の修正で、意図した挙動に戻すもの
- Issue の整理（引き継ぎ事項を記録して閉じる）

製品コードに触れない **試験のみ・文書のみの PR は、最終 head の必須 CI と1系統の独立レビューでよい**（2026-11-14 本人指示）。製品 hook を含む変更を試験のみと分類しない。製品コード変更・削除 PR は90条件 GPU 回帰を実行する。レビューの自己承認、必須 CI の免除、保護回避は行わない。

判断に迷う場合は、個別承認・安全停止条件を除く範囲で **進めたうえで報告する**。

### 都度の承認が必要なもの
- プロダクトの機能・挙動・見た目が変わる変更（新機能、UI の変更、ルックの変更）
  - レーン 5（メッセージ表示と画面表示の整理）は本人が書いた指示書に沿う変更なので、**表示を変える PR（PR-B〜F）ごとに、画面全体の変更前／変更後スクリーンショットと文言の変更一覧、Android 手動回帰記録を示して本人が見た目を承認**する。規則と部品だけで画面を変えない PR-A は承認不要。
- GPU 基準画像の採用と更新（見た目の基準になるため）
- 配布（プレリリース・リリース）
- 実機の操作
- 原本や保存データに影響しうる変更
- 依存ライブラリの追加で、権限・通信・アプリの容量に大きく影響するもの（顔検出のライブラリなど）

### 止めて確認する条件（従来どおり）
原本の変化、別写真の混入、資源の不正な解放、意図しない再試行、帯と全画面の GPU の不一致。CPU との数値差と旧速度目標の未達は、止める条件にしない。

## 7. 注意点

1. **applicationId（`dev.cinematic.p0`）と署名の鍵（`2E84FE61…`）は変えない。** 変えると上書きできず、アプリのデータが消える。
2. **2-2（GPU 基準画像との回帰試験）は、CPU 経路の削除とリファクタリングの前に必須。**
3. **AVD の回帰試験は CI で自動では動かない。** GPU やルックに触れる PR のマージ前と、CPU 経路の削除・リファクタリングの各 PR の前には必ず実行する。Mesa CI への移行（2-9）までの暫定。
4. **AVD は1枠。** 優先順位は、第2節の v0.1.0 クリティカルパス → #290 待ち時間中の PR-F → その他。重大な安全問題は別途停止して確認する。
5. **リファクタリングは D0 に書いた範囲だけ。** 小さな PR に分ける。
6. **24MP では CPU 側の RAM の使用量が増える。** GPU のメモリ上限（128MiB・192MiB）はテクスチャだけが対象。写真を開くときの制限（#260）と並行動作での使用量を実機で確かめる。
