# 撮影からDNG表示までの最小統合確認（#107 / #78）

この文書は統合後の**未実施の手順**。実機結果や性能予算ではない。本人が許可した端末操作と検証用素材だけで行う。
署名・配布・権限設定の変更や新たな撮影の許可を、この手順から推定しない。
詳細な計測方法・API比較は[性能調査](../specs/015-stage-clear-android/research.md)、原本の契約は
[保存契約](../specs/016-raw-capture-lifecycle/contracts.md)を参照する。

## 開始条件と記録

- 対象のmain SHA、APKの版・build種別・ABI、OS版、Pixel実機/エミュレータ/ホストの区別を記録する。
  異なる署名のAPKへの上書きやデータ消去を必要条件にしない。
- DNG decode → R7土台 → Stage Clear（既定0.5）→ 表示転送のどこまで動くか、実装と画面表示を照合する。
  trial decodeをR7済み・Stage Clear済みと呼ばない。未接続ならその段までの結果として止める。
- 入力は本人が選んだ端末内の検証用DNGを1つ。寸法・bytes・向き・処理上限を記録し、表示は長辺1024以下から始める。
  原本の名前/URI/画像/端末識別子を公開しない。共有原本は1つ、現像前後のfingerprint検証に成功すること。
  原本を変更・削除して試すケースは、使い捨て合成素材を使える隔離エミュレータへ分ける。
- 電源・充電・温度状態、他アプリ/撮影処理の有無を記録する。まず単発。成功するまで反復や高解像度化をしない。

## 最初に行う6ケース

| ケース | 操作と確認する結果 | 記録するもの |
|---|---|---|
| 1 単発表示 | 左下の一覧/Filesから1つ選択。向き・寸法・色空間・実際の処理段階の表示を確認。表示用結果だけならJPEG公開を成功扱いにしない | 入力選択→表示、原本確認/decode/R7/look/表示変換の各区間（取得できた範囲） |
| 2 戻る・選び直し | 確認中/現像中に一覧へ戻り、別素材または同じ素材を再選択。古い結果/失敗が新しい要求を上書きしない | 中断要求時刻、旧処理終了、次処理開始、遅い結果の採否 |
| 3 背景・再生成 | 現像中に背景へ移動して復帰。別試行で画面再生成も確認。非協調native/kernelが終了するまでは次のrendererを開始しない | lifecycle、実行中処理数、permitの保持/解放、表示世代 |
| 4 撮影へ戻る | 現像中に撮影画面へ戻る。旧処理の停止/終了とカメラ再開の順序・待ちを確認。撮影自体は別途許可がある場合だけ1回行う | 戻る→preview再開、中断→旧処理終了、撮影要求/受付/保存完了の各時刻。重複実行の有無 |
| 5 失敗・再試行 | 隔離環境の合成素材で読取失敗/途中cancelを起こし、次の正常要求が完了するか確認。失敗結果を表示成功にしない | FD/参照/permitの解放、例外種別、再試行結果。写真や例外中のパスは公開しない |
| 6 小さい連続試行 | 1〜5に問題がなければ同じ表示用入力を最大3回、毎回終了を待って実行。画面を閉じた後も観測する | 全runの時間、メモリ、GC/熱、残留処理。メモリ増加の有無は観測結果として記録 |

中断は要求であり完了ではない。`StageClearLook.shouldStop`は処理境界で確認し、kernel途中を止めない。
coroutineのcancelだけでnative処理やFDが解放されたとみなさない。旧処理の終了を観測できなければ
ケース2〜4の直列性は**未確認**とする。状態モデルのテスト成功で補わない。
撮影要求後も旧現像が続く場合は、その重複・待ち時間を残し、撮影応答合格にしない。

## 時間とメモリは別のrunで観測する

最初の単発では無計測時の体感・エラー有無を記録し、次に同じ条件で単調時計の区間またはSystem Traceを使う。
ストップウォッチなら「操作→表示の手動計測」と明記し、kernel時間にしない。
process起動後の初回と、同一processの後続runを分ける。単なる後続3回をJIT安定済みbenchmarkとは呼ばない。
未計装の区間を0msとせず「未取得」にする。中断待ちと、permit待ちも処理時間から消さない。

メモリrunでは既存のAndroid Studio Profiler等を使い、開始前・処理中・表示後・画面終了後を同じ方法で観測する。
Java/Kotlin heap、native、graphics、process PSS/RSS、GCを区別し、取得できない項目は未取得とする。
サンプリング間隔と計測ツール/overheadを記録し、最大サンプルは「観測最大値」と呼ぶ。
前後差・heap使用量・ホストJVMのcheckpoint最大値をprocessの真のpeakにしない。
割当記録/heap dumpを採るrunの所要時間は、通常runの性能と比較しない。強制GCやlargeHeapは追加しない。

OOM/ANR、原本検証の失敗、古い画像の混入、二重実行、撮影/保存への影響があれば該当試行を停止する。
メモリが戻らない観測だけでleakと断定せず、次の反復や12MPへの拡大より先に保持関係を調べる。
表示用が動いても全解像度/JPEG書き出しの合格ではない。12MP試験は別の容量確認と単発計画を立てる。
