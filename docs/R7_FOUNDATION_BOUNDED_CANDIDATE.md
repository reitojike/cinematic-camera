# Bounded R7 foundation row candidate

Base: main `a3beed6a365906621db5d623384ae7c7739a94a5`. This is an isolated, unmeasured candidate. Production saves still use one foundation worker by default. The private synthetic-DNG probe can explicitly select two workers for a later same-APK comparison.

The original-size R7 pipeline already parallelizes profile, vibrance, crisp, and skin rows. Tone analysis needs whole-image percentiles, and tone application reads a synchronized shared field. Foundation is a per-row pixel transform but receives a caller-supplied foundation skin ROI callback. This candidate runs foundation on the existing bounded two-worker queue **only** when its ROI is the exact built-in `OriginalMask.NONE` singleton. A different mask callback remains on the caller thread even if it yields all zeros; an absent ROI must not be confused with a detector reporting no face. The later face guard and its possible NEAR_WHITE→Mist→Orton→Character retry are unchanged.

Each worker owns a copy of its input row and a private width-sized ROI array. The existing `OriginalRasterWorkspace.mapParallelRows` limits two workers and four in-flight rows, retains unfinished worker ownership, and writes rows in order. The foundation formula and its within-row RGB operation order are unchanged. The new checks occur before the ROI callback, after mask validation, and after one full row calculation. Cancellation during `R7Base.foundation` may therefore finish the current row before worker shutdown; this candidate does not promise a fixed stop latency. Additional worker arrays and queued rows scale with row width, not frame area. No new full-frame buffer or external face detector is added.

Focused JVM tests are prepared to compare serial/two-worker raw float bits at the foundation and final output for small horizontal and vertical synthetic images and several strengths, verify that an external all-zero ROI callback stays on the caller, and inject worker cancellation and failure before checking owner cleanup. These tests and APK build have **not yet run** because the shared local AVD/Gradle resource window belongs to the design task. Remote CI and a later dedicated local AVD run are needed before adoption. The probe supports synthetic 64×48 and 1024×768 DNGs. A useful A/B must use the same APK, input, settings, warmup and reversed order, and compare foundation stage, whole save, observed managed/native/PSS maxima, input and JPEG hashes, and cleanup. Pixel, 12/24MP speed and real-photo appearance remain unmeasured.
