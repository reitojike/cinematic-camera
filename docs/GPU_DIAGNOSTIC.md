# GPU 合成診断（製品未採用）

この診断は #237 の実機判断材料を用意する独立アプリです。写真を読み込まず、合成データだけを生成します。撮影、現像、保存の製品入口には接続しません。CPU の golden は変更しません。

## ビルドと通常試験からの隔離

通常の debug / release は GPU 診断 source set を含みません。明示指定でのみ独立アプリを作ります。CIでは専用APKをコンパイルするだけで、GPU試験・EGL初期化は実行しません。

```powershell
.\gradlew.bat :app:assembleGpuDiagnostic -PcinematicGpuDiagnostic=true --no-daemon
```

applicationId は `dev.cinematic.p0.gpudiagnostic` です。既存の一時デバッグ署名を使い、署名鍵の新規作成や配布先の変更はしません。`profileable` な非 debuggable 版で、製品の起動Activity、保存サービス、写真・カメラ・音声権限を除外します。

合成 instrumentation はさらに `cinematicGpuDiagnosticTests=true` を指定してコンパイルします。専用テストでも `gpuPixelProbe=true` がなければ EGL 初期化前にスキップします。`isolated=true` も必要です。実機を使用するときは、その回のユーザー許可と接続を確認してから行います。

## 入口と結果

独立アプリの起動だけでは処理しません。ボタンを押したときだけ Foreground Service で次を実行します。

- 小型の正しさ確認: 257px の HDR・暗部合成入力、強度 0.25 / 0.5 / 1.0。
- 1024px 全Look比較: CPU 経路と、Glow の最小半径 bloom だけの GPU ぼかし、および Orton GPU 合成を含む経路を比較。
- 12MP ぼかし単体: 4000×3000 の合成入力を64行ずつ生成し、BOX縮小とBILINEAR復元を行う。原寸の全画像配列は保持しない。
- 12MP Orton単体: 一定色の合成入力を256行ずつ生成し、64行ずつGPU合成する。各256行でEGL文脈を作るため、その初期化時間も含む保守的な試作値。CPU比較時間はGPU処理時間に含めない。

`GpuDiagnostic` ログに時間、最大8bit差、差のある画素数と全画素数、暗部の新しい平坦な隣接点、GPU rendererを出します。「比較順を逆にする」でCPU/GPUの順を交互にできます。速度比較時はメモリ観測をオフにし、別の回で「メモリ観測」をオンにすると100ms周期の managed/native 観測最大を出します。PSS はさらに別測定とします。写真・素材名・撮影情報・端末識別子は出しません。

## 判定と制約

- 1024pxの対象ぼかし＋Orton GPU合成は、転送・同期・readbackを含む合計30msを目安にします。この試作ではEGL初期化も含みます。CPU側のOrton field準備と全Look時間は別記します。
- プレビューは全Lookで最大2段以内。そのうえで実機GPUと実写で目視の再判定が必要です。数値だけでは製品採用しません。
- 保存採用は現像全経路で最大1段以内が条件です。12MPの単体試験はこの条件を検証しません。DNGデコードからJPEGまでの合格へ読み替えません。
- 暗部の平坦化カウントは検出補助であり、目視のバンディング判定の代わりではありません。
- メモリは観測最大で、100msより短いピークを保証しません。GPUテクスチャ量とプロセス全体のPSSは別の量です。
- エミュレーターのGPU rendererと実機は異なります。時間は参考値であり、採否はPixel 9aで決めます。
- 全体の判定・縮小ぼかしの格子は既存CPU定義を参照します。Mistの判定を帯ごとに再計算しません。見送った全工程融合 #210 を再導入しません。

## 背景・取消

API 35以降は `mediaProcessing`、API 33–34は `dataSync` の Foreground Service を使います。通知を出したあと専用スレッドで EGL の所有権を保持します。ホームへ戻る・画面消灯と、前面に残す場合を区別して記録します。

「取り消す」は協調取消で、帯とGPU処理の区切りで観測します。終了時にGPU資源とメモリ採取スレッドを解放します。プロセス終了後に処理を自動再開しません。写真・一時JPEG・MediaStoreへの書き込みはありません。背景診断の成功は、製品保存の中断・復旧・撮影との両立の合格を意味しません。

## 次の判断

R7はこのGPU試作に含めません。実機のGPU時間とCPUのR7残留時間を併せて、明るさ変更時のR7前半の保持案との役割分担を決めます。保存4候補・プレビュー内訳/並列候補・準備が整えば50ms自動計測と同じ機会へまとめます。実機の回数・順序・所要時間は #208 の統合手順で確定します。
